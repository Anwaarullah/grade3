# Writing a Maths Mission activity

Each activity is one plain JavaScript file in `js/activities/<id>.js`, loaded by a
`<script>` tag in `index.html`. There is no build step and no ES modules, so the site
works on any static host and when `index.html` is opened from disk. Wrap the file in an
IIFE and use the global `MQ` object.

`js/activities/which-unit.js` is a complete working example. Read it first.

## Shape of a file

```js
(function () {
  'use strict';
  var MQ = window.MQ, el = MQ.el, U = MQ.util;

  MQ.register('my-activity', {
    learn: [                      // teaching screens, shown first (2–4 is typical)
      function (stage, api) { ... },
    ],
    practice: {
      count: 8,                   // number of practice questions
      render: function (stage, api) { ... }   // draw question number api.index
    }
  });

  // Styles used only by this activity go in a <style> tag added here.
  // Prefix every class with a short activity code (e.g. .rl- for ruler-lab).
  document.head.appendChild(el('style', { 'data-activity': 'my-activity' }, '...css...'));
})();
```

The page title, icon, summary, parent tips and book page references come from
`js/curriculum.js`. Do not repeat them in the activity file.

## The `stage` and `api`

`stage` is an empty, centred flex column. Append your elements to it. It is cleared
automatically between screens.

Available on every screen (learn and practice):

| api | what it does |
|---|---|
| `api.say(text, mood)` | Bolt the robot says something (speech bubble, read aloud if voice is on). mood: `'happy'`, `'think'`, `'cheer'`, `'oops'`. Short sentences. |
| `api.feedback(text, kind)` | Message bar under the stage. kind: `'good'`, `'try'`, `'info'`. |
| `api.sound(name)` | `'correct'`, `'wrong'`, `'star'`, `'click'`, `'pop'`. |
| `api.lockNext()` / `api.unlockNext()` | On a learn screen, stop the child moving on until an interaction is done. |
| `api.next()` | Go to the next screen yourself. |
| `api.later(fn, ms)` | `setTimeout` that is cancelled when the screen changes. Always use this instead of `setTimeout`. |
| `api.cleanup(fn)` | Run `fn` when the screen changes (remove window listeners, intervals). |
| `api.index`, `api.count` | Which screen this is, and how many there are in this phase. |
| `api.util` | Same as `MQ.util`. |

Practice screens also have:

| api | what it does |
|---|---|
| `api.level` | 1, 2 or 3: first third, middle third, last third of the questions. Use it to make questions harder. |
| `api.check(ok, hint, mistake)` | **Call this when the child answers.** `ok` true/false. If false, `hint` is shown (make it a helpful nudge, never just "wrong") and `mistake` (a short parent-readable phrase, e.g. `'Read the end number instead of end − start'`) is logged for the parent dashboard. If true, an optional `hint` string replaces the default praise. The core handles sounds, the robot, first-try scoring, the Next button and stars. Calls after a correct answer are ignored. |
| `api.onReveal(fn)` | After 2 wrong tries a "Show me" button appears. `fn` must show the correct answer and how to get it (fill the box, highlight the right choice, animate the working). Always provide one. |
| `api.tries()` | Wrong tries so far on this question. Use it for a stronger hint on the 2nd try. |
| `api.isAnswered()` | True once the question is finished. |

Questions are generated by `render`. To avoid repeats, build a deck when `api.index === 0`
(also when the deck is missing, because the test tool jumps straight to any index) and
read `deck[api.index]`.

## Building blocks (`js/components.js`)

* `MQ.el(tag, attrs, ...children)` / `MQ.svg(tag, attrs, ...children)`: create HTML/SVG. attrs supports `class`, `style` (object), `html`, `text`, `onclick` etc.
* `MQ.ui.choices(options, onPick, {columns})`: big answer buttons. Options are values or `{label, value}` (label may contain HTML). Returned element has `.mark(value, 'good'|'bad')`, `.disable()`, `.enable()`.
* `MQ.ui.numberInput({unit, half, prefix, onSubmit(num, raw)})`: answer box + Check button (Enter works). `half: true` adds a "+ ½" button and accepts `13½`, `13.5`, `13 1/2`. Returns `{el, input, focus(), disable(), enable(), clear(), setValue(), good(), bad()}`. Append `.el`.
* `MQ.ui.grid({cols, rows, cell, pad})`: square grid SVG with `.svg`, `.under` (fills), `.layer` (shapes/labels on top), `.x(col)`, `.y(row)`, `.cellAt(point)`, `.fill(c, r, cls)`, `.half(c, r, corner, cls)`.
* `MQ.ui.ruler({from, to, cm, broken})`: SVG centimetre ruler `<g>`; `.moveTo(x, y)`, `.xOf(n)`, `.width`.
* `MQ.ui.drag(svgRoot, handle, {start, move(p, dx, dy), end})`: mouse/touch drag inside an SVG, in SVG coordinates. Returns an unbind function: pass it to `api.cleanup`.
* `MQ.ui.svgPoint(svg, event)`: pointer position in SVG coordinates.
* `MQ.ui.sum([3, 3, 3, 3], 12, 'cm')`: shows "3 + 3 + 3 + 3 = 12 cm" as chips.
* `MQ.ui.lesson(title, html)`, `MQ.ui.prompt(html)`: big teaching text and question text.
* `MQ.util`: `rand(a, b)`, `pick`, `shuffle`, `range`, `clamp`, `fmt(13.5)` → "13½", `parseNum`, `same(a, b)`.

CSS variables you can use: `--ink`, `--ink-soft`, `--paper`, `--paper-2`, `--line`,
`--accent` (the planet colour), `--gold`, `--good`, `--good-bg`, `--try`, `--try-bg`,
`--info-bg`. Shared classes: `.btn`, `.btn-ghost`, `.chip`, `.prompt`, `.lesson`.

## Teaching rules for this learner

* Grade 3, Cambridge Stage 3. He is fine with + and − but **weak at × and ÷**. Use
  repeated addition and counting in jumps as the bridge, and make arrays visible.
* A parent sits beside him on a **laptop** (mouse + keyboard). Clicking and dragging
  are both fine. Keep reading short: one idea per screen, big text.
* Show, then ask: every learn screen should have something to look at or touch, not just
  text.
* Wrong answers get a specific, kind hint that points at the likely mistake. "Show me"
  explains the answer visually.
* Use realistic numbers that match the textbook and workbook ranges.
* Space and robots theme: rockets, robots, planets, aliens, space stations.
  Keep it light; the maths matters most.
* Everything must be original. Do not copy text or pictures from the books.

## Testing

```bash
node tools/smoke.js my-activity --out /tmp/smoke
```

This opens every learn and practice screen in headless Chromium, saves screenshots
and reports JavaScript errors or empty screens. Look at the screenshots. For
interactions (drag, click, answer checking), write a short Playwright script.
`require('playwright')` works from any directory.
